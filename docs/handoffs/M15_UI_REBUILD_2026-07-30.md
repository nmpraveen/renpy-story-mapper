## 2. Reader rendering changes (`app.js`)

### Arm semantics
`storyArmPresentation(controlKind)` now keys on the **control** kind only. Previously it
returned early on outcome, so 391 of 571 arms read "Rejoin route" — including 120 player
choices and 271 condition paths. Now: 189 "Player picks", 382 "Condition path".
The outcome moved to its own line via `storyOutcomeSentence()` / `appendStoryTargets()`.

### De-duplication
- `storySummaryWithoutOutcome()` strips a trailing "Rejoins at X." from an arm summary when
  the outcome line already states it (was stated up to 3× per arm)
- `storyPromptRepeatsArms()` suppresses the control prompt when it is just the arm captions
  joined by " / " (backend `_control_title` behaviour)
- `appendStoryContinuations(..., seen)` takes a per-event `Set` so one merge is announced once;
  the 213 hardcoded "Paths continue together / Continue from this proven story point." rows are
  gone, replaced by the merge's human name when the binding has one
- `appendStoryBadges()` no longer emits the "Reachable" badge (was 678 no-op badges);
  unreachable/unresolved still show
- `appendStoryWarnings()` summary renamed from "N technical warnings" to "Python detail" —
  it carries facts like `Python label: start`, not warnings

### Prose
`renderStoryProse()` replaces the single 5,247-char `<p>` with `white-space: pre-line`.
Splits on blank lines, promotes `Beat title — body` and leading title lines to `<h4
class="story-prose-beat">`, emits `<p class="story-prose">` per paragraph.
`appendProgressiveStoryDetail()` skips the prose block entirely when the body equals the
title (merge rows carry no prose of their own and were echoing their own title).

### Expressions
`storyTitleNode()` splits titles beginning `Requires: `, `Check whether `,
`Routes: Check whether ` into a small-caps lead + `<code class="story-title-expression">`.
Display only — the string is unchanged. 408 occurrences on the review project.

### Structure
- Event titles now sit in `<h3 class="story-event-heading">` and every event carries
  `id="story-event-N"` (was: buttons, no headings, no anchors)
- Forks with more than `STORY_STACK_THRESHOLD` (4) arms render `.story-arms.is-stacked`
  (vertical spine + elbows) instead of columns — 6 forks in this game
- Nested routes are `<details class="story-descendant-route">` with a
  `Inside <arm> · N branch points` summary; open when `countStoryForks() <=
  STORY_OPEN_FORK_LIMIT` (2). This is where most of the scroll reduction came from.

### Navigation (new)
- `buildStoryNavigation()` / `storyChapterCandidates()` derive positional scroll landmarks at roughly one per
  `STORY_CHAPTER_SPAN` (6) events, clamped to 8–24. Slot 0 is forced to event 1; other slots
  pick the least machine-looking title in their stride window.
- These landmarks are a reading index only. They do not define narrative chapters, group story
  events, or change the Python-owned execution structure.
- `updateStoryReadingPosition()` drives "N of 111" and the rail progress bar.
  Throttled with `setTimeout` **not** `requestAnimationFrame` — rAF is starved when the tab
  is not compositing, which silently froze the indicator during testing.
- `scrollStoryTo()` uses instant scroll past `STORY_SMOOTH_SCROLL_LIMIT` (4000px); CSS
  `scroll-behavior: smooth` over a 46,000px jump reads as a hang.
- `markActiveChapter()` / `nearestChapterId()` — an IntersectionObserver was tried first and
  removed; it raced with the scroll handler and never fired on initial load.
- `applyStorySearch()` filters rendered events client-side and reports "N of 111 events match".
  **This replaces a broken feature:** the old box called `api.storyReaderSearch(mapRevision,…)`,
  which throws `TypeError: Story reader search request is invalid` because the whole-game path
  leaves `mapRevision` null. No network request was ever made.

### Connector geometry (pure CSS, no JS measurement)
```
.story-arms { grid-template-columns: repeat(var(--story-arm-count, 2), minmax(0, 1fr));
              padding-top: calc(var(--story-stem) + var(--story-drop)); }
.story-choice-control::after            /* stem: control bottom → bus */
.story-arm::before                      /* drop: bus → card top, at left: 50% */
.story-arm:not(:last-child)::after      /* bus segment: width calc(100% + var(--story-fork-gap)) */
```
With equal `1fr` columns, `calc(100% + gap)` from one arm's centre lands exactly on the
next arm's centre, so the bus self-assembles for any arm count without division in `calc()`
(which is unreliable with a `var()` divisor). Measured at 1920px: needed 728px, actual
726.2px — the ~2px delta is sub-pixel `fr` rounding.

### Width and measure
- `.story-arm` `max-width: min(34rem, 100%)` (544px hard cap) → `minmax(0, 1fr)` columns
- `.story-inline-summary` `max-width: 72rem` (1152px ≈ 144 chars) → `--story-measure: 68ch`
- `.story-reader-shell` is now `minmax(13rem,15rem) minmax(0,1fr)` (rail + guide)

**Important:** the progressive block must explicitly reset the base `.story-arm` and
`.story-choice` rules (`border: 0; background: transparent; padding: 0`). Those base rules
serve the paged reader; the old progressive block reset them and I initially dropped the
resets, which put an 11px offset inside every arm.

### Other
- Selection moved off `--accent-soft` (terracotta) to a neutral inset, so red stays reserved
  for true endings per the Phase 05 contract
- Breakpoints changed from 1050/780/620/480 to 1240/900/620; below 900px forks stack
- `prefers-reduced-motion` honoured; `scrollStoryTo` also checks it

## 6. Still open (backend, out of this change's scope)

1. **Machine label names.** 335 of 602 destination badges read like
   `Rejoins at Shared 4 0 WG continuation`. Root cause is `_humanize()` at
   `src/renpy_story_mapper/story_map_v2/whole_game_reader.py:760`, which splits a Ren'Py
   label on `_` and rejoins with spaces, so `shared_8_5_2_wn_clean_continuation` becomes
   `shared 8 5 2 wn continuation`; line 255 then appends "continuation" a second time.
   Also `_control_title` (583) emits `Check whether <python>` and `_arm_caption` (592)
   emits `Requires: <python>` / `Otherwise` — 216 and 166 occurrences.
   The UI now typesets these legibly but cannot fix the text.

2. **State provenance is not a link.** 392 disclosures say
   `Earlier state controls this route: loi, gen, no_boys_8_5_2.` — raw variables, no anchor
   back to the decision that set them. `GOAL.md:44` requires the back-link. Needs Python to
   emit provenance edges (assignment site → owning event ordinal → human choice caption)
   before the UI can render them.

3. **Cross-label route topology is still flattened.** `whole_game_reader.py:338-384` appends
   every reachable label as a top-level event in traversal order. Local choices render as trees,
   but downstream label events are not attached beneath the arm that reaches them. Alternate
   route scenes can therefore appear consecutive; events 108-111 are two pairs of sibling Faye
   routes that converge later, yet the reader stacks all four in the main timeline. The next
   correction should compose label-to-label transitions into the same progressive tree used by
   the accepted Terrance proof.
